# Instructions for Claude (both Jelle's and Tinus's)

This repo is the Mannenkeuken guild dashboard. Read README.md first. The working instructions (guild sync + dashboard, in Dutch) are in `docs/instructies.md`: follow them, and update that file in the same pull request whenever sync or dashboard behaviour changes. At the start of every conversation: summarise what the other person merged since this person's last PR, and list the other's open `[bezig]` draft PRs. When you start work: open a draft PR titled `[bezig] …` right away; every PR body has *Wat*, *Waarom* and *Voor de ander*.

- Site copy is in **English**, everywhere (labels, notes, placeholders, addon texts in the database). Talk to Jelle/Tinus in **Dutch**. The sheet's Status value "Gestopt" stays Dutch in the data (the sync compares with it) but is shown as "Quit" with `statusLabel()` from `js/players.js`: never show a raw sheet value without checking it. Addon priorities are Must-have / Recommended / Optional / Alternative.
- Plain static HTML/CSS/JS served by GitHub Pages. No frameworks, no build step, no npm.
  Supabase is loaded from `https://esm.sh/@supabase/supabase-js@2` as an ES module.
- Every page: `<link rel="stylesheet" href="css/style.css">` and a module script that calls `renderHeader()` from `js/layout.js`. New page → add it to the `pages` list in `js/layout.js` (six menu places; a page that belongs to a place goes in its third element so the place lights up) or, for a Guild page, to `GUILD_TABS`. Profile, player page, developer mode and switch player live in the menu under the player's name.
- Escape all user/sheet text with `esc()` from `js/sheet.js` before putting it in HTML.
- Database changes: edit `supabase/schema.sql` (idempotent: `if not exists`, drop/create policies) and tell the user to run it in the Supabase SQL Editor. Keep Row Level Security on every table: read for all, write only own rows (`user_id = auth.uid()`).
- Never commit secrets (service_role key, Discord Client Secret, the guild code). The anon key in `js/config.js` is fine.
- Login: "Choose your player" + guild code (anonymous Supabase session linked to a player in `members` by `join_guild()`). A player can have several browsers: use `mine(user, row.user_id)` from `js/supabase.js` for "is this mine?" and `user.ids` / `user.player`, never `row.user_id === user.id`. RLS: personal rows via `same_player(user_id)`, shared things via `is_member()`.
- Work on a branch (`jelle/...` or `tinus/...`) and open a pull request. Never push to `main` directly.
- Look: dark fantasy theme in `css/style.css` (near-black panels, gold trim, crimson buttons; headings in Cinzel from Google Fonts). All colours are CSS variables (`--gold`, `--panel`, `--text`, …): use `var(--…)` in HTML and scripts, never hex codes. Use no Blizzard/Wowhead artwork, logos or fonts; icons and the logo are our own drawings. Class icons (`classIcon(cls)` in `js/classicons.js`) show next to the player name in the header. Profession badges (`professionIcon(name)` / `professionLabel(name)` in `js/proficons.js`, our own drawings) show with professions; the name links to the profession on Wowhead (hover tooltip, Wowhead's own icon switched off with `iconizeLinks: false`).
- Every local CSS link and JS import carries `?v=__V__` (e.g. `import { esc } from './js/sheet.js?v=__V__'`, inside js/: `'./supabase.js?v=__V__'`). The deploy workflow replaces `__V__` with the commit id so browsers never mix old and new files. Keep it on new imports too, and on images referenced from CSS (`url('../img/x.png?v=__V__')`; the workflow stamps `css/*.css` as well).
- `data/items.json` (the full WoW: Forever item list) and `data/tradeable-items.json` (only tradeable items: Bonding 0/2/3; used by the Trade Market search) are generated by `tools/update-items.mjs` via the "Update items" workflow, and `data/quests.json` (quest list, from Questie for Forever) by `tools/update-quests.mjs` via "Update quests" (both daily + manual). Names members type that are not in a list yet (new in Forever) are suggested to everyone as plain text (`withTyped` in `js/itemsearch.js`), except on the Trade Market: there only an item from the official tradeable list can be posted. Don't edit them by hand; those bot commits are the only direct pushes to `main`. Quests link to `questUrl(id)` in `js/quests.js` (Wowhead Forever). `data/blizzard-characters.json` (level, professions and last login per character, from the Blizzard API) is written by `tools/update-characters.mjs` via the "Update characters" workflow (manual for now); settings in `data/blizzard-config.json`; read it with `loadBlizzard()` in `js/players.js`. Don't edit it by hand.
- After every deploy the workflow "Check site after deploy" (`tools/check-site.mjs`, Chrome over the DevTools port, no dependencies) opens the main pages and reports to Checks/Fixes through `report_deploy_check()` (secret `DEPLOY_CHECK_SECRET`; its hash is in `private.settings`). A new page that must stay healthy goes into the `PAGES` list there.
- Every logged-in player can send a problem or idea from the account menu (`openReport()` in `js/report.js` → database function `submit_ticket()`); it becomes a card on the developers' Fixes / Ideas board. The orange count next to DEV comes from `updateDevNewBadge()` in `js/layout.js` (`dev_ticket_news()`; `dev.html` clears it with `dev_mark_tickets_seen()`).
- Developer mode (`dev.html`, 5 clicks on the class icon; only `DEVS` in `js/layout.js` = `is_dev()` in the database): tabs Ideas and Fixes (ticket boards in `dev_tickets`, `kind` = idea / fix: Open → In progress on someone's name → Done; urgency, emoji reactions via `toggle_ticket_reaction()`, comments in `dev_ticket_comments`), changes per day, checks, checklist (`dev_checks`) and messages between the developers (`dev_messages`). Found a bug you don't fix right away, or an idea for later? Add it as a ticket. `isDevMode(user)` gives extra powers (delete any listing). After a change, add what still needs testing to `dev_checks`.
- Dates and times are always shown in Dutch time, 24-hour clock: `toLocale…String('en-GB', { timeZone: 'Europe/Amsterdam', hourCycle: 'h23', … })`.
- Every delete / "mark as done" action asks `confirm('Are you sure …?')` first.
- Items link to Wowhead Forever (`wowheadUrl(id)` in `js/itemsearch.js`); pages showing items load Wowhead's `tooltips.js` for hover tooltips and call `refreshTooltips()` after rendering.
- Money: show amounts with `goldHtml(copper)` from `js/gold.js` (gold, silver and copper coin icons, our own drawings) and progress with `goldBar()`; use `formatGold()` only for plain text such as a `confirm()` question.
- Activity (last login): use `activityOf(lastLogin)` and `ACTIVITY` from `js/players.js` (active / quiet / inactive / unknown) and the `.activity` + `.dot-*` styles; don't make your own thresholds. The data comes from `loadBlizzard()`.
- Characters come from two places: the guild sheet (leading for level and professions) and the site (`profiles` = main, `alts`). `js/players.js` merges them (`loadCharacters()`); use it instead of reading one source. `players` maps sheet player name ↔ Discord name (kept up to date by the guild sync).
- Shared things (bank items, bank gold, addons, players) may be edited by any member (guild code); personal things (profiles, alts, listings, reservations, sign-ups) only by their owner.
- Reservations (bank + market) always store who reserved (`reserved_by`) and for which character.
